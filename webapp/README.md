# Review Diagnostic

A generalized, self-serve version of this project's review-diagnostic
methodology: paste any Play Store app and get a statistical read on what's
actually driving negative reviews, and whether it's gotten better or worse
recently — no app-specific hardcoding, works on any app.

- **Up to 200 reviews**: instant, rendered in-browser.
- **201–1,000 reviews**: queued as a background job, results emailed (via
  Gmail's SMTP relay) since the run is too slow to wait on.

Reviews are split into two cohorts by recency (most recent half vs. prior
half), complaint categories are discovered directly from review text
(embedding + clustering, not a fixed keyword list), and each category's share
of the Negative band is compared across cohorts with a two-proportion
z-test, Cohen's h effect size, and Benjamini–Hochberg correction. Nothing is
stored — every run is stateless.

## Running it locally

```bash
pip install -r requirements.txt
python server.py
```

Opens at `http://localhost:7860`. The async/email path needs `GMAIL_ADDRESS`
and `GMAIL_APP_PASSWORD` environment variables to actually send mail (a Gmail
App Password, not the account password -- Google Account → Security → App
passwords, requires 2-Step Verification); without them, the instant path
(≤200 reviews) still works fully, and async jobs will queue and run but fail
at the send step (logged, not silent -- see `[email]` lines in server logs).

## Deploying

This app is host-agnostic (checks both `SPACE_HOST` and `RENDER_EXTERNAL_URL`
for its own keep-alive self-ping) and binds to `0.0.0.0:$PORT`. See
[`render.yaml`](../render.yaml) at the repo root for a ready-to-use Render
Blueprint.

## Layout

```
server.py                    FastAPI app: routes, job queue, keep-alive thread
static/
  index.html                   Page shell (form, result containers)
  app.js                        fetch()-based form handling, no page reloads
  theme.css                     Design system (light, no external chart libs)
review_diagnostics/
  scrape.py                    Play Store scraping
  snippets.py                   Clause-level snippet splitting
  cohorts.py                     Auto-split into older/recent cohorts
  discovery.py                    Unsupervised category discovery (embedding + clustering)
  measurement.py                   Assigns every snippet to its category
  stats.py                          z-test, Cohen's h, BH correction
  report.py                         Renders both the in-app HTML and the email
  pipeline.py                        Orchestrates the whole run
  email_delivery.py                  Gmail SMTP relay calls
```

## Why FastAPI instead of Gradio

The app originally used Gradio's `Blocks`/`queue()` UI. Live testing on
Render surfaced a specific, reproducible failure: the backend consistently
finished a run in well under a second (confirmed via server-side logging),
but Gradio's SSE-based queue didn't reliably deliver the result back to the
browser — reproducible across fresh tabs and sessions, with the queue's
`queue/data` stream getting aborted mid-flight. Rather than depend on
Gradio's queue internals working a specific way behind Render's proxy, the
UI was rewritten as a small FastAPI app: two JSON endpoints
(`/api/lookup`, `/api/run`) called via plain `fetch()`, no SSE, no queue.
The actual report — KPI strip, donut chart, diverging bar charts, confidence
table, filter chips — is unchanged; it was already just HTML generated by
`report.py` and styled by `theme.css`, so only the app shell around it
needed replacing.

## Why Gmail instead of a transactional email API

The app originally used Resend. Its free tier's shared sending address
(`onboarding@resend.dev`) can only deliver to the account owner's own
verified email — any other recipient is rejected outright, confirmed live
in production logs. That's not a Resend quirk; every transactional email
provider requires verifying a custom domain (DNS records proving
ownership) before sending to arbitrary recipients, as a standard
anti-abuse measure. Without a domain to verify, Gmail's own SMTP relay
sends from an address already owned and controlled by the operator's
Gmail account to any recipient, no domain verification needed at all.
